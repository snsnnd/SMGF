# E组最小展示方案

## 1. 目标

`E` 组当前不再承担“救主线”的任务，而承担：

1. 提供一个能展示系统综合能力的正例；
2. 提供一个能说明系统当前局限的反例；
3. 为论文的展示层和边界层准备素材。

因此，`E` 组的目标不是“全部打通”，而是：

> 在最小试验量下尽快找到一个可展示的 `E1` 正例，并保留一个失败边界作为局限性说明。

## 2. 当前已知事实

基于 `outputs/group_E_validation_v1/summary_metrics.csv` 和后续小探索：

1. 当前 `E1/E2/dense easy/dense medium/dense hard` 的正式 validation 全部失败；
2. 主导失败模式是 `obs_collision_rate = 1.0`，通常还伴随 `agent_collision_rate = 1.0`；
3. 直接套用 `C` 组的结构增强参数只能改善最小间距，不能显著压低障碍碰撞；
4. 将 `E1/E2` 的目标速度降低到 `0.70/0.85` 倍后，`M7 success_rate` 仍然为 `0`；
5. 因而 `E` 组当前的主要矛盾更偏向“障碍穿越几何与目标追踪耦合”，而不是单纯内部结构支撑不足。

## 3. 为什么从 E1 开始

建议从 `E1` 而不是 `dense easy` 开始，原因是：

1. `E1` 障碍最少，最容易归因；
2. `E1` 目标速度最低，是 `E` 组里最轻的综合挑战；
3. `E1` 如果仍然完全打不通，就说明问题不在“障碍太多”，而在综合耦合本身；
4. 一旦 `E1` 出现非零成功率，就已经足够作为综合展示正例候选。

## 4. 最小展示性正例搜索顺序

建议按以下固定顺序推进：

### 第一步：只做 E1

只看：

1. `scene = e1_tracking_single_obstacle`
2. `method = M7`

目标：

1. 先把 `success_rate` 从 `0` 拉到非零；
2. 不急着引入多方法对照。

### 第二步：先降任务难度，不先大改机制

优先试：

1. 目标速度缩放：`0.50 / 0.60 / 0.70 / 0.80`
2. `t_pred` 扫描：`0.3 / 0.7 / 1.0 / 1.3`

原因：

1. `E1` 是综合展示场景，不需要一开始就坚持最激进速度；
2. 先找到“能展示的正例”比先证明“最难配置也能成功”更重要；
3. 这一步成本最低，也最容易出非零结果。

### 第三步：只在必要时引入 C组候选结构参数

若第二步仍然全失败，再试：

1. `fixed floor = 0.65`
2. `k_s = 3.4`
3. `k_t = 1.5`
4. `r0 = 1.9`

但必须注意：

1. 这组参数是为 `C` 组高压通道定制的；
2. 在 `E1` 中它只应当被视作综合展示时的工程候选，而不是新的全局默认配置。

### 第四步：如果 E1 找到正例，再回到 E2

仅当 `E1` 已经出现非零成功率后，再考虑：

1. `scene = e2_tracking_sparse_obstacles`
2. 重复同样的缩放与少量参数验证

目的：

1. 看展示性正例能否从单障碍推广到稀疏障碍；
2. 不让 `E2` 先把整个搜索空间拖得过大。

## 5. 推荐的展示性成功标准

对 `E1`，当前建议的展示性成功标准为：

1. `success_rate > 0`
2. `obs_collision_rate` 明显低于 `1.0`
3. `agent_collision_rate` 不恶化
4. 能保留基本追踪闭环，而不是只换来某个单项指标好看

若能达到更高标准，则更好：

1. `success_rate >= 0.10`
2. `obs_collision_rate <= 0.80`

这已经足以作为论文中的“展示性正例候选”。

## 6. 推荐的反例保留方式

即使 `E1` 找到正例，也建议保留一个明确失败边界，例如：

1. `dense medium`
2. 或 `s5_dense_tracking_hard`

用途：

1. 说明当前系统在复杂障碍综合场景下仍有明显边界；
2. 与 `E1` 的正例形成一正一反的展示结构。

## 7. 停止条件

`E1` 搜索建议设置停止条件，避免无穷扩张：

1. 若降速 + `T_p` 扫描后仍然全失败，再尝试一次 `C` 组结构候选；
2. 若连上述组合仍然全失败，则暂时停止 `E` 组救活；
3. 把 `E1` 明确保留为失败展示与后续方向，而不是继续无上限调参。

## 8. 一句话结论

> `E` 组当前最合理的最小展示策略是：先只攻 `E1`，先通过降速度与少量 `T_p` 扫描搜索非零成功率，再在必要时引入 `C` 组结构候选；目标是尽快获得一个可展示正例，而不是继续把 `E` 组当作主线救火场。
