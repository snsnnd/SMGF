# 实验优化更新报告

## 1. 先回答论文观点是否合理

结论不是“论文观点错了”，而是：

> 论文观点在研究思路上是合理的，但当前实现与现有实验结果还不足以完整支撑所有主张。

更具体地说：

1. **合理的部分**：
   `S3` 和 `S5-0` 已经说明，SMGF 在开阔或低难度层级中能够实现可运行的协同收缩与目标跟踪，这证明“状态调制引导场”不是没有物理意义的空想法。
2. **尚未被证明的部分**：
   `Omega` 驱动的窄通道柔性通过，目前仍没有被现有实现验证成功。
3. **当前真正的问题**：
   不是论文主线毫无合理性，而是当前控制结构对“障碍约束下的群体内部安全”和“通过后的不拥挤保持”处理还不够好。

因此，最准确的说法是：

> 你的论文方向有研究价值，也有局部正证据，但不能在当前结果基础上直接宣称双状态调制已经在复杂障碍环境中被充分验证。

## 4. 核心实验结果分析

### 4.1 S3：开阔环境围捕收缩仍然成立

结果摘要：

1. `M4 success_rate = 0.8`
2. `M6 success_rate = 1.0`
3. `M7 success_rate = 1.0`
4. 三者 `collision_rate = 0`

解释：

1. 这说明在无障碍开阔环境下，调制型方法的围捕收缩能力是存在的。
2. `M6/M7` 相对 `M4` 更稳定。
3. 这部分支持论文中“调制拓扑比固定拓扑更利于后期收缩”的观点。

结论：

`S3` 仍然是目前最能支持论文主线的正结果场景。

### 4.2 S5-0：无障碍移动目标跟踪已经成功

结果摘要：

1. `M4 success_rate = 1.0`
2. `M6 success_rate = 1.0`
3. `M7 success_rate = 1.0`
4. 三者 `collision_rate = 0`

解释：

1. 这说明当前系统在“移动目标 + 无障碍”层级上已经可用。
2. 这也说明论文主线不是从根本上错误，因为目标预测、基本导航和群体协同闭环已经能够工作。
3. 但这里 `M7` 没有明显优于 `M6/M4`，说明在没有环境压力时，`Omega` 本来就不应成为主导因素。

结论：

`S5-0` 提供了一个重要基线：

> 当前实现的问题不是连最基本的移动目标任务都做不到，而是带障碍后的避障与群体安全冲突仍未解决。

### 4.3 S5-1 / S5-2：一旦加入障碍，系统立即暴露结构缺陷

结果摘要：

1. `S5-1` 中 `M4/M6/M7 success_rate = 0`
2. `S5-1` 中 `obs_collision_rate = 1.0`
3. `S5-1` 中 `agent_collision_rate = 1.0`
4. `S5-2` 中 `M4/M6/M7 success_rate = 0`
5. `S5-2` 中 `obs_collision_rate = 1.0`
6. `S5-2` 中 `agent_collision_rate = 1.0`

解释：

1. 当前失败不是“仅仅没形成包围”，而是已经出现了障碍碰撞与内部碰撞同时存在。
2. 这说明 S5 的关键瓶颈正是你前面判断的那一类：
   避障、目标跟踪与群体间距保持三者之间存在明显冲突。

结论：

你的分级思路是对的。当前实现必须继续向更低复杂度剖开问题，而不能直接把 `S5-dense` 当主验证场景。

### 4.4 S4：Omega 机制仍未被现有实现证明成功

结果摘要：

#### S4-easy

1. `M4 success_rate = 0.2`
2. `M6 success_rate = 0.0`
3. `M7 success_rate = 0.0`
4. `M4 agent_collision_rate = 0.8`
5. `M6 agent_collision_rate = 1.0`
6. `M7 agent_collision_rate = 1.0`

#### S4-medium

1. `M4 success_rate = 0.6`
2. `M6 success_rate = 0.0`
3. `M7 success_rate = 0.0`

#### S4-hard

1. `M4 success_rate = 0.6`
2. `M6 success_rate = 0.0`
3. `M7 success_rate = 0.0`

解释：

1. 这轮实验没有支持“Full SMGF 在窄通道中优于固定拓扑”这个结论。
2. 相反，当前数据表明 `M4` 比 `M6/M7` 更好。
3. 而且失败主因已经被新指标清楚地定位出来：
   主要是 `agent_collision`，不是 `obs_collision`。
4. 这很关键，因为它说明现阶段的问题更像是“群体内部挤压与通过后聚集”，而不是单纯没能绕开障碍。

结论：

基于当前实现，**不能**把 `Omega` 机制写成已经被实验正面验证的主结论。

更保守、也更诚实的说法应该是：

> 当前实验表明，SMGF 在窄通道问题上的主要瓶颈来自通道约束下的群体内部安全维持，现有标量 `Omega` 调制还不足以稳定地把拓扑软化转化为更高通过率。

### 4.5 S6：高速目标拦截仍未打通

结果摘要：

1. `M4/M6/M7 success_rate = 0`
2. `agent_collision_rate = 1.0`
3. `obs_collision_rate = 0`

解释：

1. 当前 S6 的核心问题不是障碍，而是高速目标下的群体内部间距失稳。
2. 这意味着现在还不能从 `S6` 得出“预测时间存在最优区间”的主结论。
3. 当前更应该把 S6 看成“执行能力与群体间距控制尚未匹配”的问题。

## 5. 对论文观点的最终判断

本轮更新后，我对论文观点的判断比之前更清楚：

### 5.1 不是没有合理性

有两个场景已经提供正证据：

1. `S3`：开阔环境下围捕收缩成立
2. `S5-0`：无障碍移动目标跟踪成立

这说明：

1. 预测导航 + 状态调制协同不是无效结构
2. 你的论文主线不是从根本上错误

### 5.2 但当前不能过度宣称

当前不能直接写成已经充分成立的观点包括：

1. `Omega` 明显提升窄通道通过率
2. Full SMGF 明显优于固定拓扑
3. 高速目标场景下预测机制已稳定提升综合围捕性能

原因很直接：

1. `S4` 当前反而是 `M4 > M7`
2. `S6` 当前全部失败
3. `S5-1/2` 也全部失败

## 6. 这轮实验说明了什么

新的指标把问题定位得更明确了：

1. **不是所有失败都一样**。
2. 当前最主要的失败模式是：
   “几何趋势形成了，但内部安全守不住”。
3. 因此当前实现的主要短板不是目标吸引，也不是完全不会避障，而是：
   障碍压力下的群体纵横向组织方式还不对。

这也解释了为什么你提出“方向性软化”是有道理的：

1. 当前标量 `rho_i` 只能整体削弱拓扑项
2. 它无法区分“横向该软化、纵向该保留”

## 7. 下一步建议

基于这轮结果，建议按以下顺序继续：

1. 在 `TrialMetrics` 中继续补充“首次障碍碰撞时间”和“首次智能体碰撞时间”。
2. 在 `S4` 中增加“碰撞发生区段”分析，区分入口、通道内部和出口后碰撞。
3. 优先尝试方向性拓扑软化增强版 `M9`。
4. 对 `S6` 先降低目标速度并重新做 `T_p` 扫描，避免把“执行极限”误判为“预测失效”。
5. 当 `S4-easy` 和 `S5-1` 稳定成功后，再扩大到 `30/50/100 seeds`。

## 8. 本轮结论一句话总结

> 这轮代码优化和新实验说明：你的论文方向本身是有合理性的，但当前实现只在开阔/低难度层级上被验证成功；一旦进入障碍约束场景，主要瓶颈转移为群体内部安全与拓扑软化方式不匹配，因此论文主张需要保留核心思路、收紧表述，并继续围绕窄通道和带障碍跟踪做结构性改进。
